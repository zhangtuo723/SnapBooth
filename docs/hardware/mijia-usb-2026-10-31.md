## 与现有代码和 iPad 实测的关系

- `Tools/MijiaUSBHelper.c` 使用接口 2 和 `0x06/0x86`，与本次实际描述符一致。`WinUSB_Eg` 是接口名称，不表示 iPad 可以使用 Windows 的 WinUSB API。
- 标准接口 0 是双向 USB Printer Class `07/01/02`。它的存在不能使 iPad 的系统网络打印接口直接读写 USB 端点。
- 用户确认打印机开机后用数据线直接连接 A16 iPad，测试期间 Mac 断开。Build 34 报告显示相机内容/控制访问均已允许、多次刷新已经执行，但 ImageCaptureCore 和 ExternalAccessory 列表均为 0。这证明这两条 App 可见路径在本次测试没有发现设备，不证明物理 USB 没有枚举，也不单凭接口类排除 MFi。
- Build 35 的 15 秒倒计时、完成事件及报告保存另已在 A16 / iPadOS 27.0.1 验证；该次验证时打印机没有连接 iPad，不用于判断打印兼容性。

## 当前工程结论

打印任务和照片上传协议在 Mac 已经验证，A16 的通用 USB 端点访问仍无可用公开实现路径。本次描述符也没有给出可转用的 PTP 或 USB 网络入口。不能将现有 `libusb` / 辅助进程代码直接迁入 A16 iPad。

Apple 目前将 iPadOS DriverKit 限制于 M 系列 iPad；标准 USB-only 无驱动打印支持也不能从 Mac 推导到 iPad。若换用支持 DriverKit 的 iPad，仍需开发 USB 驱动并取得适当权限；若保留 A16，则需另选已支持的打印链路或增加 USB 主机桥接设备。
